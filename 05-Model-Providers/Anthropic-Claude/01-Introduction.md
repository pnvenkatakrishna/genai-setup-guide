# 1. What Is Claude?

**Claude** is a family of AI models developed by **Anthropic**.

Claude models can be used for tasks such as:

* Understanding text
* Generating text
* Writing and analyzing code
* Summarizing information
* Reasoning over complex problems
* Working with images
* Using tools
* Building agentic applications

Anthropic's current model lineup includes **Claude Fable 5.1, Claude Opus 5.5, Claude Sonnet 5.5, and Claude Haiku 4.5**. Model capabilities, pricing, availability, and lifecycle information can change, so model selection should always be based on the current Anthropic model documentation.

### Current model IDs

| Model             | Claude API ID       | General use                                       |
| ----------------- | ------------------- | ------------------------------------------------- |
| Claude Fable 5.1  | `claude-fable-5-1`  | Demanding reasoning and long-horizon agentic work |
| Claude Opus 5.5   | `claude-opus-5-5`   | Complex projects, agents and coding               |
| Claude Sonnet 5.5 | `claude-sonnet-5-5` | Balance of speed and intelligence                 |
| Claude Haiku 4.5  | `claude-haiku-4-5`  | Fast, cost-efficient workloads                    |

**Important:** Model IDs are not permanent. Always check the current model page before copying a model ID into a new project.

Official documentation:

https://platform.claude.com/docs/en/models/overview

# 2. What Does "API" Mean?

Before understanding the Claude API, understand the word **API**.

API stands for:

> **Application Programming Interface**

An API is a defined way for one software system to communicate with another software system.

Think about a restaurant.

```text
You
 │
 │ Order
 ▼
Waiter
 │
 │ Request
 ▼
Kitchen
 │
 │ Food
 ▼
Waiter
 │
 │ Response
 ▼
You
```

The waiter acts as an interface between you and the kitchen.

You don't walk into the kitchen and operate the cooking equipment yourself.

Similarly, your application does not directly operate Anthropic's model infrastructure.

Instead:

```text
Your Application
       │
       │ API Request
       ▼
   Claude API
       │
       ▼
 Claude Model
       │
       │ API Response
       ▼
Your Application
```

The API provides the defined interface through which your application communicates with Claude.

---

# 3. What Is the Claude API?

The **Claude API** is Anthropic's programmatic interface for accessing Claude models.

It is a RESTful API available at:

```text
https://api.anthropic.com
```

The Claude API provides multiple APIs for different use cases.

Some important APIs include:

```text
Messages API
Message Batches API
Token Counting API
Models API
Files API
Skills API
```

Anthropic also provides additional agent-related APIs, including beta APIs for managed agent infrastructure.

For beginners, the most important starting point is:

> **Messages API**

The Messages API is used to send messages to Claude and receive responses.

Its endpoint is:

```text
POST /v1/messages
```

So the complete endpoint is:

```text
https://api.anthropic.com/v1/messages
```

---

# 4. Claude Chat vs Claude API

This distinction is extremely important.

Many beginners think:

> "I have a Claude account, so I automatically have an API."

That is not the right mental model.

### Claude Chat

You interact with Claude through a user interface.

```text
Human
  │
  │ Types prompt
  ▼
Claude Chat
  │
  ▼
Claude
  │
  ▼
Response shown on screen
```

### Claude API

Your application interacts with Claude programmatically.

```text
Application
  │
  │ Sends API request
  ▼
Claude API
  │
  ▼
Claude Model
  │
  │ Returns response
  ▼
Application
```

### Side-by-side

| Claude Chat                     | Claude API                       |
| ------------------------------- | -------------------------------- |
| Human-focused interface         | Developer-focused interface      |
| Browser/app interaction         | Programmatic interaction         |
| Prompt entered manually         | Prompt generated by code         |
| Response displayed to user      | Response returned to application |
| Useful for direct conversations | Useful for building applications |

---

# 5. Claude Subscription vs Claude API

Another common misunderstanding:

```text
Claude subscription
        ≠
Claude API access
```

A subscription for using Claude through the consumer/application experience is separate from API usage.

The Claude API is managed through the developer platform and its associated authentication and billing mechanisms. Anthropic explicitly documents Claude subscriptions and API/Console usage as separate products.

Therefore:

```text
Using Claude Chat
       │
       └── Does not mean your application is automatically configured for API access


Using Claude API
       │
       ├── Console
       ├── Authentication
       ├── API access
       └── API usage/billing
```

---

# 6. What Is Claude Console?

**Claude Console** is Anthropic's developer platform.

It provides the management layer around your Claude API development.

You can use the Console for things such as:

* API keys
* Workspaces
* Billing
* Usage
* Organization administration
* API experimentation
* Development workflows

The Console is available at:

https://console.anthropic.com/

Anthropic's API documentation identifies the Console as the place where developers obtain API keys and manage API access.

# 8. What Is an API Key?

An **API key** is a credential used to authenticate your application with the Claude API.

For direct API requests, Anthropic currently supports API keys as static secrets.

Conceptually:

```text
Your Application
       │
       │ API Key
       ▼
   Claude API
       │
       │ Authenticate
       ▼
    Request
```

For direct HTTP requests, the current recommended authentication header is:

```http
Authorization: Bearer YOUR_API_KEY
```

Anthropic also continues to support the legacy `x-api-key` header.

When using an official SDK, you normally do not manually construct these headers. The SDK handles the required authentication and API-version headers for you.

---

# 9. API Key Types

Anthropic currently supports different API-key types.

The important ones for this guide are:

### Personal key

A personal key represents you as the user.

It is appropriate for:

* Personal development
* Learning
* Prototyping
* Individual projects

### Service account key

A service account key represents a service account rather than an individual developer.

It is more appropriate for:

* Shared applications
* Team-owned services
* Automated workloads

Anthropic's current authentication documentation recommends a personal key for your own development and a service-account key for shared applications.

---

# 10. What Is a Workspace?

A **Workspace** is a logical area inside a Claude Console organization.

A workspace can be used to separate:

* Applications
* API keys
* Usage
* Access
* Spend

For example:

```text
Organization
│
├── Default Workspace
│
├── Learning
│
├── RAG Project
│
└── Production
```

A beginner may only need one workspace.

A larger team may use separate workspaces for different environments or projects.

Anthropic's current API documentation supports workspace-scoped API keys. A key scoped to one workspace can avoid manually specifying a workspace ID in each request. A multi-workspace key can require the `anthropic-workspace-id` header.

We will cover this in detail when we create the API key.

# 11. How Authentication Fits Into the Request

A simplified API request looks like:

```text
Application
    │
    │
    ├── API Key
    │
    ├── Model
    │
    └── Message
    │
    ▼
Claude API
    │
    ├── Authenticate
    │
    ├── Validate request
    │
    ├── Resolve workspace
    │
    ├── Check model/access
    │
    └── Process request
    │
    ▼
Claude Model
    │
    ▼
Response
```

This is why an API key is not simply "a string you paste into Python."

It is part of the application's authentication mechanism.

# 12. Authentication Options

The Claude API currently supports three main authentication approaches:

| Authentication               | Typical use                                       |
| ---------------------------- | ------------------------------------------------- |
| API key                      | Local development, prototypes, scripts, servers   |
| Workload Identity Federation | Cloud, CI/CD, Kubernetes and production workloads |
| App Attest                   | Direct API access from distributed iOS/macOS apps |

Anthropic recommends API keys as the easiest way to get started. For production workloads that already have a cloud or platform identity, Workload Identity Federation can eliminate the need for long-lived static secrets. App Attest is intended for supported distributed Apple-platform applications.

### Beginner path

```text
API Key
   ↓
Environment Variable
   ↓
Python SDK
   ↓
Claude API
```

### Production identity path

```text
Cloud / CI/CD / Kubernetes
           ↓
Platform Identity
           ↓
Workload Identity Federation
           ↓
Short-lived credential
           ↓
Claude API
```

We will start with the first path.

# 14. What Happens When We Send a Request?

Suppose our application asks:

```text
Explain Kubernetes in simple words.
```

The flow is:

```text
1. Python application
          │
          ▼
2. Anthropic SDK
          │
          ▼
3. Authentication
          │
          ▼
4. Claude API
          │
          ▼
5. Selected Claude model
          │
          ▼
6. Model processes the request
          │
          ▼
7. Claude generates response
          │
          ▼
8. API returns structured response
          │
          ▼
9. Python application reads response
          │
          ▼
10. User sees the answer
```

The developer does not need to implement the HTTP protocol manually when using the official SDK.

---

# 15. Why Use the Official SDK?

You can call the REST API directly using HTTP.

However, Anthropic provides official SDKs that simplify integration.

The SDK handles things such as:

* Authentication headers
* API version headers
* Request formatting
* Response handling
* Retries
* Timeouts
* Streaming support
* Type-safe interfaces, depending on the SDK

Anthropic's API documentation recommends client SDKs as the easier integration path for supported languages.

For this guide we will use:

```text
Python
   ↓
Anthropic Python SDK
   ↓
Claude API
```

# 18. Expert Note — Don't Start With Code

A common beginner mistake is to immediately write:

```python
client.messages.create(...)
```

without understanding:

* Where the API key comes from
* Which organization/workspace is being used
* How billing works
* Which model is selected
* How authentication works
* How secrets should be stored
* What happens when the key expires
* What happens when the model changes

A professional developer understands the system first and then writes the code.

That is why this guide follows:

> **Concept → Architecture → Setup → Authentication → Code → Verification → Security → Production**
